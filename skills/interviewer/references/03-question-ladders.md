# 提问阶梯与题库

用法：**不要照着念**。这些是方向标，你要根据候选人的简历现场生成问题。

题库分两部分：通用阶梯（任何方向都用）和分方向题库。

---

## 一、通用阶梯

### L0 自我介绍（限时 60-90 秒）

开场唯一一个「宽」问题。**必须计时。**

```
先用一分半钟介绍下自己，重点讲和这个岗位相关的经历。
```

**在测什么**：不是口才，是**取舍能力**。90 秒里他选择讲什么、放弃什么，直接反映他知不知道这个岗位要什么。

**红牌**：从头到尾念简历时间线，没有一处「我判断」「我选择」。

---

### L1 事实核查

从简历里挑一个项目，问：

```
你简历上这个 XX 项目，具体哪一部分是你写的？
```

**在测什么**：参与深度。**注意听「我们」和「我」的比例。**

**追问**：

- 「团队几个人？你排第几？」
- 「这块代码现在还在跑吗？」
- 「如果让你现在重新实现，你会怎么改？」

---

### L2 技术选型

```
为什么这里用 A，不用 B？
```

**在测什么**：技术判断力。**这层是真正拉开差距的地方**——L1 只能筛掉吹牛的，L2 才能看出水平。

**关键**：不要接受「A 更流行」「大家都用 A」。

**追问**：

- 「当时比较过哪些方案？」
- 「A 有什么缺点？你怎么绕的？」
- 「如果当时必须用 B，你会怎么设计？」

---

### L3 实现细节

```
具体怎么实现的？关键的数据结构 / 参数是什么？
```

**在测什么**：是不是真动手做过。**编的方案在这一层一定会崩。**

**追问**：

- 「这个参数为什么是 512 不是 1024？」
- 「数据量多大的时候这个方法会失效？」
- 「给我画一下数据流。」

---

### L4 反事实

```
如果流量涨十倍，会怎样？
```
```
如果这个约束去掉，你的方案还成立吗？
```
```
如果让你把它迁到另一个场景，你会改哪里？
```

**在测什么**：是否理解原理而不是记住了方案。**照抄方案的人在这一层一定答不上。**

---

### L5 复盘

```
做这个项目踩过最大的坑是什么？
```
```
现在回头看，哪里做错了？
```

**在测什么**：复盘能力和诚实度。

**红牌**：「没什么坑，挺顺利的」——要么没深度参与，要么不会反思。

---

## 二、大模型 / Agent 方向

### RAG 与检索

- L2：你的文档怎么切分的？为什么这么切？
- L3：用了什么 embedding 模型？维度多少？为什么？
- L3：检索 top-k 取几？为什么？
- L4：**检索不到的时候怎么办？** ← 几乎是必考题
- L4：你怎么知道检索质量好不好？测什么指标？
- L4：混合检索（BM25 + 向量）比纯向量好在哪？什么场景反而更差？
- L5：有没有遇到过「检索对了但模型答错」的情况？怎么定位是哪一环的问题？

**必问的一题**：「你怎么知道你的 RAG 效果好还是不好？」
答不出 eval 方案的，直接暴露没有生产经验。

### Agent 与工具调用

- L2：你的 Agent 用了几个工具？怎么决定调哪个？
- L3：工具调用的参数错了怎么办？
- L3：怎么防止 Agent 陷入死循环？
- L4：**上下文满了怎么办？** ← 高频
- L4：多步任务里怎么保证不丢状态？
- L4：如果工具调用有副作用（比如下单、发消息），你怎么保证幂等？
- L5：你的 Agent 上线后失败率多少？主要失败在哪类任务？

### 记忆

- L2：短期记忆和长期记忆你怎么分的？
- L3：记忆怎么写入？什么时候写？
- L4：记忆冲突了怎么办？（新信息和旧记忆矛盾）
- L4：记忆检索召回不准，你怎么排查？

### 评估（分水岭）

- L2：你有测试集吗？多少条？怎么来的？
- L3：测试集是自己标还是模型生成？质量怎么保证？
- L3：用什么指标？为什么用这个而不用那个？
- L4：模型版本升级后，怎么知道没变差？
- L4：**离线指标涨了线上没涨，你怎么定位？** ← 高级必考
- L5：有没有一批「模型永远做不对」的样本？你从里面看出了什么？

### 生产工程

- L2：单次请求延迟多少？多少花在模型上？
- L3：成本怎么算的？一次对话多少钱？
- L4：模型 API 挂了怎么办？
- L4：并发上不去，瓶颈在哪？
- L4：怎么防止 prompt 注入？

---

## 三、Java 后端方向

### 并发与 JVM

- L2：项目里哪里用了多线程？为什么？
- L3：锁的粒度是多少？为什么不是更粗/更细？
- L3：线程池核心参数怎么定的？队列满了会怎样？
- L4：`HashMap` 1.8 之后为什么改红黑树？扩容时并发会怎样？
- L4：线上出现过 GC 问题吗？怎么定位的？看什么指标？
- L5：有没有写过出并发 bug 的代码？怎么发现的？

### 数据库

- L2：你项目里最大的表多少行？查询慢吗？
- L3：这个查询走索引了吗？你怎么确认的？
- L3：事务隔离级别用的哪个？为什么？
- L4：分库分表之后，跨库查询怎么办？
- L4：主从延迟导致读到旧数据，你怎么处理？
- L5：有没有过线上慢查询拖垮数据库？怎么救的？

### 缓存与分布式

- L2：缓存了什么？为什么缓存这个？
- L3：缓存穿透/击穿/雪崩分别怎么防的？
- L3：缓存和 DB 的一致性怎么保证？延迟多少可接受？
- L4：分布式锁用的什么？锁超时了但业务没跑完怎么办？
- L4：服务 A 调 B 超时了，你怎么知道是 A 的问题还是 B 的？
- L5：有没有出过线上故障？时间线是怎样的？

### 工程习惯

- L2：你们的测试覆盖到什么程度？单测还是集成测？
- L3：怎么灰度的？出问题怎么回滚？
- L4：你怎么监控一个刚上线的接口？

---

## 四、算法方向

- L2：你这个任务为什么用这个指标？和业务目标对齐吗？
- L3：baseline 是什么？为什么选它？
- L3：数据从哪来的？清洗了什么？标签怎么打的？
- L4：**这个提升跑了几次？方差多大？** ← 最容易露馅
- L4：做过消融吗？哪个模块贡献最大？
- L4：离线涨了线上没涨，你怎么定位？
- L5：有没有一个实验反复失败？你最后怎么处理的？

---

## 五、逆向问法（高级候选人用）

给高级/专家级候选人加这些，普通候选人不用：

- 「如果我说这个方案是错的，你会怎么反驳我？」
- 「你觉得你这个方案最大的风险是什么？」
- 「团队里有人不同意你的技术选型，你怎么处理？」
- 「这个技术半年后会被淘汰吗？为什么？」
- 「如果你现在有一周空闲，你会优化项目的哪一块？」

**在测什么**：技术判断力、抗压、有没有自己的观点。**答「您说得对」的，直接扣分。**
